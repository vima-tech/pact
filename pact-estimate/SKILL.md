# /pact-estimate — 估算门（禁止拍脑袋给数字）

> 创建日期: 2026-08-02

**凭直觉给的数字会被当成承诺，且必然漏掉阻塞缓冲与后 50% 的落地量。**
方法真源：`$CORE/references/effort-estimation.md`——先读它再动手。

```bash
CORE="$(ls -d ./.claude/skills/pact ~/.claude/skills/pact 2>/dev/null | head -1)"
```

若 `$ARGUMENTS` 含 `--help`：只输出 `bash $CORE/scripts/pact-help.sh` 的内容然后停止。

## 第一步：定位物料 + 停止条件

1. 定位规则与 `/pact-run` 相同（给路径用路径；0 份指去 `/pact-new`；多份 `AskUserQuestion` 选）。
2. **S1 停止条件**：`P5` 只要有一条缺 `T1` 验收 → 回答「无法估算，缺哪几条」，**不给数字**。
   工具会强制这条（exit 1）。给数字比说不知道更有害。

## 第二步：四个前提（缺一个不出数，向用户批量确认）

`AskUserQuestion` 一次问齐（已有 `estimate.md` 或对话里已明确的项不重复问）：
① 交付形态（demo 5× / 产品级 2.5×）；② 执行者 AI 经验（熟手 55–65% / 生手 ~30%）；
③ 项目类型（新建 / 自有二开 ~80% / 他人遗留改造可能负收益）；
④ ②类未知业务约束占比 r₂（客观判据：`source-merge.md` 里「实测有、文档无」的条目数）。

## 第三步：算术交给工具，不许手算

```bash
cp $CORE/templates/rate-card.json <物料目录>/    # 首次：费率卡改成执行者实测值
bash $CORE/scripts/pact-estimate.sh <物料目录>/PACT.md              # 可持续卡（排期/承诺用）
bash $CORE/scripts/pact-estimate.sh <物料目录>/PACT.md --card=peak  # 峰值卡（只看最快多快，禁止承诺）
```

产出 `<物料目录>/estimate-calc.md`。**T3 清单必须人眼复核**：工具输出每条判定理由，
逐条问「这条真的比一个 CRUD 难十倍吗」，误判的调整分层正则或单条降级并注明。

## 第四步：产出与纪律

1. 对外承诺用手写的 `<物料目录>/estimate.md`（模板 `$CORE/templates/estimate.md`，
   完整格式：前提/假设/阻塞源/停工线/三条线）；已存在则更新并注明重估原因与日期。
2. 三条线回写 `T5`、停工线回写 `T3`、工期与团队回写 `P7`；PACT 已冻结 → 记 `changelog.md`。
3. **五条硬规矩**（详见方法文档）：对外只报交付线（× 阻塞缓冲 1.5–2，取并行最大值不求和）；
   骨架完成线只覆盖约 50%，禁止用它承诺；多人并发有天花板（3 人只快约 28%）；
   停工线按可追溯性排序，范围可缩、形态不可退化；**PACT 写得好不是下调工期的理由**。

## 报告格式（最终消息必须包含）

三条线（明确标出「对外只承诺交付线」）· 分层结果（T1/T2/T3 条数与占比，T3 复核结论）·
四前提取值 · 并发方案（若用户问了人数）· 前提变了要重估的触发条件。
