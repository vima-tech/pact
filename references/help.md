# PACT 使用速览

> 创建日期: 2026-07-26 ｜ 人类向。AI 执行细则见 `SKILL.md` 与 `references/agent-protocol.md`。

**PACT = Product · Architecture · Contracts · Tests**
把 PRD / SDD / SPEC / 验收标准 / 施工范围熔成**一份 `PACT.md`**，再按它严格施工。

它干两件事，缺一不可：
1. **生成规格** —— 访谈补白 → 写四层 → 完备性门 → 冻结
2. **按规格落地** —— 按 R-ID 施工 → 自动验收 → 四道机检兜底

验收标准只有一条：**一个对本项目一无所知的人或 AI，只读 `PACT.md` 就能开工。**

---

## 一、怎么开口

在**项目根目录**跟 AI 说：

```
/pact 做一个给中小企业用的报销审批系统      # 新项目从零
/pact --feature 给管理端加批量导出            # 已有项目加大需求（最常用）
/pact --merge docs/prd.md docs/技术方案.md    # 多份打架的文档熔成一份
/pact 继续                                    # 中断后接着干
/pact --help                                  # 看这份速览
```

模式不写也行，它会自己判（有没有实质代码、给的是文档还是一句话），
**并在开场第一句说明判成了什么、依据是什么**——判错了当场纠正即可。

## 二、五种模式

| 模式 | 什么时候用 | 走哪些工序 |
|---|---|---|
| `--new` | 空项目 / 只有一个想法 | S0–S11 全套 |
| `--feature` | 已有代码 + 一个大需求 | 全套，且必做存量八维评估 |
| `--merge` | 有一堆互相打架的旧文档 | 全套，且必做差异裁定 |
| `--build` | PACT 已冻结，只要施工 | S0 → S10 → S11 |
| `--audit` | 只想体检现有 PACT | S0 → S8，出报告不改代码 |

附加开关：
- `--review` 每道闸门停下等你确认（默认不停，但产物随时落盘，可打断）
- `--level=full|feature` 完备度档位。新项目 `full`（30 个锚点全填），加需求 `feature`（核心 16 个）

## 三、你需要参与的只有三个时刻

十二道工序绝大部分 AI 自己走。你真正要出手的：

| 时刻 | 它做什么 | 你做什么 |
|---|---|---|
| **S1 访谈门** | 按十二类过一遍，把「猜错代价大」的问题**批量**弹给你 | 一次答完（每问带 2–4 个选项和推荐项）。代价小的它自己取默认并标注 |
| **S2 熔合门**（仅多份文档时） | 列出文档间的矛盾逐条上桌 | 裁定「以哪个为准」。**它不会替你择优采用** |
| **S8 后请求冻结** | 三道门全过 | 扫一眼 `PACT.md`，确认是你要的东西 |

冻结后它就按 R-ID 一个个实现 + 自动验收，直到覆盖表全绿。

## 四、会在你项目里生成什么

```
PACT.md            ← 唯一要读的规格：需求(R-ID)、契约、决策、验收全在里面
CLAUDE.md          ← 怎么写代码的惯例（与 PACT 分工：它管"怎么写"，PACT 管"写什么"）
.pact/
  board.md         ← 工序状态表，看进度就看这个
  interview.md     ← 访谈记录       source-merge.md ← 差异裁定
  assessment.md    ← 存量评估       cold-read.md    ← 冷读门报告
  coverage.md      ← R-ID 覆盖表    changelog.md    ← 冻结后的变更记录
```

`PACT.md` 是**自足**的——换个人、换个 AI，只读它就能接着干，不用翻聊天记录。

## 五、你唯一需要配合的事：代码标注

每段业务代码要带 R-ID 标注，AI 会自己写，但你 review 时要认得：

```js
// @pact R001            单个
// @pact R001,R002       一段覆盖多个
# @pact R014             Python / Shell
<!-- @pact R021 -->      模板 / HTML
```

**没有标注 = 无法反查 = 覆盖表就是自说自话。** 这是让"严格落地"闭环的钥匙。

## 六、四道机检（AI 说"做完了"不算数）

```bash
S=~/.claude/skills/pact

bash $S/scripts/pact-status.sh                     # 工序：走到哪了、有没有跳步
bash $S/scripts/pact-lint.sh PACT.md --level=feature   # 规格：PACT 写够了没有
bash $S/scripts/pact-trace.sh                      # 落地：代码真按 PACT 做了没有
bash $S/scripts/pact-book.sh --check               # 视图：知识库与真源有没有漂移
```

| 脚本 | 抓什么 |
|---|---|
| `pact-status.sh` | 跳步、静默略过条件工序、冻结状态不一致 |
| `pact-lint.sh` | 锚点缺失、占位符残留、R-ID 没有验收、决策没写「已否决方案」 |
| `pact-trace.sh` | **虚报**（覆盖表说做完但代码里没有）、**野生功能**（代码有但规格里没有）、漏登记、未实现 |
| `pact-book.sh --check` | 手改了生成的知识库、改了 `PACT.md` 忘了重新生成、生成物残留孤儿文件 |

收尾时 trace 要加 `--require-complete`，把"还有未实现"从提示升为失败。

## 七、中断了怎么办

会话断了、上下文被压缩、甚至换个 AI 接手，直接说 `/pact 继续`。

它会先读 `.pact/board.md` 判断在第几道工序——**不会凭记忆瞎猜、不会重新访谈你、
不会重写已冻结的规格**。你自己想看进度：

```bash
bash ~/.claude/skills/pact/scripts/pact-status.sh
# 列出 S0–S11 进度，并直接告诉你下一道该做什么
```

## 八、十二道工序一览

```
S0  定位与摄入      判模式、建骨架、读物料
S1  访谈门          十二类补白，阻塞项批量问你          ← 你参与
S2  熔合门［条件］  多来源差异逐条裁定                  ← 你参与
S3  存量评估［条件］八维评估现有代码，只读不改
S4  写 P 层         背景/用户/场景/需求(R-ID)/非目标/约束/成功定义
S5  写 A 层         结构/链路/原则/决策(含已否决方案)
S6  写 C 层         数据模型/接口/状态机/配置/权限/观测   ← 精度门槛在这
S7  写 T 层         验收清单/指标/停工线/交付前置/里程碑
S8  完备性门        lint + 反扫 + 零知识冷读门           ← 硬闸门
S9  冻结            标已冻结，此后改动走 changelog       ← 你确认
S10 施工 LOOP       按 R-ID 逐单元实现 + 自动验收
S11 收尾自检门      四道机检全绿 + 末次冷读 + 知识库已重生成
```

条件工序不适用时必须写明「已跳过（理由）」，**不许静默略过**。

## 八点四、问「多久能做完 / 报个价」时（估算门）

**别凭直觉给数字——凭直觉给的数字会被当成承诺。** PACT 在 `S7 写 T 层` 内置了估算门：

```bash
cat $S/references/effort-estimation.md      # 方法
cp  $S/templates/estimate.md .pact/          # 产出模板
```

三条最容易翻车的规矩：

| 规矩 | 为什么 |
|---|---|
| **骨架只覆盖约 50%**，且写更好的文档提不上去 | 文档从 60 分到 90 分只换来约 5% 覆盖率。规格管方向与验收，**不管编码量** |
| **对外只报「交付线」**，不报净开发时间 | 交付线 = 开发完成线 × 阻塞缓冲(1.5–2)。开发再快，卡在 HIS/等保/客户开会上也是自己背延期 |
| **停工线按可追溯性排，不按重要性排** | 不可追溯的（数据契约、追溯码采集、审计留痕）今天不做就永久缺失；可追溯的（报表、界面）随时能补。**禁止逐项降级**——范围可缩，形态不可退化 |

机检会盯着：`P7` 里写了工期/团队却没有 `.pact/estimate.md`，`pact-lint.sh` 第 10 项报 WARN。

## 八点五、把知识库跑起来看

规格写完后 `.pact/pact-book/` 里有两份东西，各有各的读者：

| 产物 | 给谁 | 怎么用 |
|---|---|---|
| `pact-book.html` | **人** | **双击打开就行**——单文件、零依赖、零外部请求，`file://` 直接跑。要发给甲方或分包方就发这一个附件 |
| `src/**.md` | **AI** | 施工时读 `src/r/R###.md` 一页即可；纯 markdown，GitHub 上也能直接浏览 |

网页版自带：三栏布局（导航 / 正文 / 当页目录）、**字段感知搜索**（`ms:M3`、`src:SRC-B`、`类型:权限`）、
★ 与里程碑过滤、R-ID 悬停预览卡、可点击的依赖图、明暗主题、打印样式。快捷键 `/` 或 `⌘K` 聚焦搜索。

> **不需要装 mdbook。** 早期版本依赖它，现在渲染层已自研——理由是它要装 Rust 二进制、
> 还要再装 mdbook-mermaid，跨机器跨项目都是摩擦，而规格是要发给外部的东西。
> `book.toml` 与 `SUMMARY.md` 仍然生成，**你想用 mdbook 也照样能用**，只是不再必需。

## 九、几个实用提醒

- **规格冻结后要改需求？** 别直接改代码。让 AI 走 S10-CR 五步：
  回 `P5` 加 R-ID → `T1` 补验收 → 改 `C` 层契约 → 记 changelog → 判断是否重跑冷读门。
- **S8 的冷读门会额外起一个 agent** 读你的 PACT（不给它任何上下文），会多花些 token，
  但这是 PACT 的定义性检验——跳过它，PACT 就退化成一份普通 SDD。
- **第一次用别拿真项目练手**。先看 `references/example-PACT.md`（一份通过全部机检的完整范例），
  特别是 `A5` 决策的「理由 / 已否决」怎么写——那就是 PACT 要求的精度。
- **然后挑一个中等大小的真需求跑 `--feature`**。不建议第一次就 `--new` 开新项目，
  那会触发完整十二类访谈，要回答的问题比较多。
- **它默认不提交代码**，改完停在未提交状态，你自己 review 后再决定。

## 十、什么时候**不该**用 PACT

- 改个文案、修个明显的 bug、调个样式 —— 直接说就行，走完十二道工序是浪费。
- 需求本身还在探索、随时会推翻 —— 先把想法聊清楚，再用 PACT 固化。
- PACT 适合的是：**新项目开局** 和 **值得先想清楚再动手的大需求**。
