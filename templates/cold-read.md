# 零知识冷读门（Cold-Start Gate）

> 创建日期: <YYYY-MM-DD>
>
> **PACT 的定义性检验。** 把「只读这一份就能开工」从口号变成可验证的一步。
> 每次跑都**追加**一节，保留历史，不要覆盖。

## 怎么跑

用 `Agent` 工具（`subagent_type: general-purpose`）另起一个**全新** agent，
**只给它 `PACT.md` 的路径，不给对话历史、不给其他文档、不给代码库背景**。

### 视角 A · 实现者（必跑）

```
你对这个项目一无所知。请只阅读 <绝对路径>/PACT.md，不要读仓库里的任何其他文件，
不要基于常识补全你认为"显然"的部分。

输出三部分：
1. 【实现计划】你打算怎么做——模块划分、动手顺序、每步产出什么。
2. 【必须追问的问题】在动工前你**必须**得到答复、否则只能靠猜的问题。
   对每个问题注明：不问会导致什么后果。
3. 【矛盾与歧义】文档内部自相矛盾、二义、或不可实现的地方，逐条给出位置。

严格要求：不要礼貌性地说"文档很完整"。你的任务是找出它不完整的地方。
如果某个信息你是靠经验补的而不是文中读到的，那就算作【必须追问的问题】。
```

### 视角 B · 反对者（`--level=full` 建议加跑）

```
你对这个项目一无所知。只阅读 <绝对路径>/PACT.md。
你的任务是**反驳这份规格**：找出它自相矛盾、不可实现、内部不一致、
验收标准无法判定、或需求与非目标冲突的地方。逐条给位置与理由。
```

## 判定标准

| 冷读结果 | 判定 | 动作 |
|---|---|---|
| 追问清单为空，且实现计划与意图一致 | **PASS** | 可冻结 |
| 提出的问题答案**已在 PACT 里** | 不算漏洞，但**表述不可发现** | 调结构/加索引/加交叉引用，重跑 |
| 必须追问背景、意图、或任何约束 | **FAIL** | 每个问题回填到对应锚点，重跑 |
| 实现计划**跑偏**（做了没要的、漏了要的） | **FAIL** | `P4/P5/P6` 表述有歧义，改写后重跑 |

**跑到 PASS 为止。** 不许"差不多了"。
